DELETE FLOW

User clicks delete.

This runs:

dispatch(removeTodo(todo.id))

Redux creates:

{
   type:"todo/removeTodo",
   payload:id
}

Reducer executes:

state.todos =
   state.todos.filter(...)

Store updates.

Redux notifies useSelector.

Todos component re-renders.

Todo disappears.

THE BIGGEST REDUX MENTAL MODEL

Everything in Redux follows:

UI
 ↓
Dispatch
 ↓
Action
 ↓
Reducer
 ↓
Store
 ↓
useSelector
 ↓
UI

It's a complete cycle.

CONTEXT VS REDUX MENTAL MODEL

UI
 ↓

 ↓

 ↓
UI
Redux
UI
 ↓
Dispatch
 ↓
Action
 ↓
Reducer
 ↓
Store
 ↓
useSelector
 ↓
UI

Redux introduces:

Action
Reducer
Store

between UI and state.

That's why Redux scales better for large applications.

MOST IMPORTANT THING YOU SHOULD REMEMBER

Redux has only one rule:

Components NEVER change state directly.

Instead:

Component
   ↓
Dispatch Action
   ↓
Reducer Changes State

That separation is the core philosophy of Redux.
